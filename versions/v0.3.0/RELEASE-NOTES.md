# v0.3.0 更新说明（相对 v0.2.0）

## 目标

用户无需 Node.js、npm、终端命令或手动维护 `registry.json`，即可安装、使用和更新插件。降低创建插件的门槛，明确插件之间的隔离与冲突规则。

## 已实现

- 插件管理器新增 **导入插件文件夹**，支持 `webkitdirectory` 文件选择，读取文件内容、严格校验路径/大小/清单后以 IndexedDB 本地快照保存。
- 支持从扩展自带 `examples/catalog.json` **一键安装 19 个离线示例**。默认仍没有启用任何插件。
- 新增 **卸载**按钮，仅删除本地安装副本，设置与数据保留以便重装。
- 用户导入新版本时必须确认，安装或更新结束均**默认禁用**，避免新代码未经再次允许执行。
- 规范简化为最少两个文件及三个清单字段 `id,name,version`；引入 `Lemon.mount` 入口助手，保留旧版 `window.LemonPlugin.mount`。
- 运行时维持**每插件独立 iframe**，设置与数据按 ID 隔离，安全请求按 iframe WindowProxy 身份验证，加载时超时可重试。
- 多全屏插件互斥启用；全屏插件显示时隐藏其他普通卡片。
- 背景控制者只允许一个，其他插件不能覆盖背景。
- 资源限制和路径过滤；静态资源加上 woff/woff2 字体读取支持。
- 完整的插件格式规范 `PLUGIN-SPEC.md`、入门手册、模板和回归测试。
- 原有 v0.2.0 打包插件清单保持兼容，核心补丁不含用户 `plugins/` 目录。

## 限制与兼容性风险

- Chrome 无法无授权自动扫描本地文件夹；安装时必须选择目录，更新源文件需手动重新导入。
- 插件安装副本存于当前 Chrome 扩展的 IndexedDB，和原始插件目录分离，卸载扩展/重建扩展 ID 时可能丢失。
- 启用“全屏”时其他卡片隐藏（仍保留启用状态），背景切换后当前插件需要重新发起背景设置请求。
- 没有签名验证、在线插件商店、CPU/内存严格限额或插件间受控共享通道。
- 原版测试在 Node 环境中跑通，但受环境 Chrome 策略限制，**尚不能宣称真实 Chrome 安装验收通过**。

## 升级

推荐备份 v0.2.0 目录，使用 `v0.3.0-core-patch.zip` 覆盖核心和工具文件（**不会覆盖 `plugins/`**），在 `chrome://extensions/` 重新加载扩展即可。现有打包插件继续由原有注册清单加载；新插件建议使用图形界面导入。升级前请不要改变现有扩展根目录路径。
